## 2. 判定规则

- **通过**：前端操作成功，后端状态与物理输出一致，且无新增错误日志。
- **修复后通过**：测试中发现问题，完成代码修复、自动测试、D2 部署并实机复测通过。
- **受外部环境限制**：系统能够正确报告外部设备或网络故障，但无法验证外部目标本身。
- **未执行破坏性动作**：关机、清空正式播放列表、删除正式媒体等不可逆或影响现场的动作，只验证保护性 UI/确认流程，不实际确认执行。

## 4. 已确认并修复的问题

### 4.1 PPT Application 代理跨放映复用导致 COM 断连

- **表现**：PPT 直接切换另一份 PPT 后出现“对象没有连接到服务器”、`Open.Slides` 或找不到放映 HWND。
- **根因**：PowerPoint 为进程级 COM 服务器；SlideShow 退出后，原 Application 代理可能失效，而旧实现仍将该代理放回预热池。
- **修复**：PPT 离场彻底退休当前 Application 代理；PPT→PPT 严格串行关闭旧放映，再 `DispatchEx` 新代理；切换期间禁止并发重建预热。
- **自动验证**：相关 47 个回归测试通过；全量 369 个测试通过。
- **实机结论**：连续 PPT 切换、视频→PPT、加载中关闭后重开均通过。

### 4.2 网页预热失败状态丢失

- **表现**：不可达网页在物理屏保持 loading，但前端显示“播放中”。
- **根因**：WebView 在预热阶段已经发出 `loadFinished(false)`，适配器接管后才连接回调，失败事件丢失。
- **修复**：预热池在 WebView 上记录 loading/success/error；适配器接管时恢复；普通打开在 `setUrl` 前连接回调。
- **实机结论**：不可达网页正确转为 error，错误信息与恢复按钮正常。

### 4.3 移动端媒体源 sticky 区域重叠

- **表现**：标题下方大块空白，分类条遮住搜索、刷新、添加。
- **修复**：移动端工具栏改为正常文档流，仅分类条 sticky 到滚动区顶端。
- **实机结论**：360/390 宽度均无覆盖，操作按钮完整可见。

### 4.4 键盘音量没有提交最终值

- **表现**：背景音乐滑块键盘值变化，但后端音量不变。
- **修复**：背景音乐复用节流滑块逻辑；键盘 keyup 确定性提交。窗口音量和视频进度同样补充键盘收口。
- **实机结论**：键盘调整后 UI 与 API 同步，随后已恢复原音量。

### 4.5 状态文案与可访问性

- 双屏时大屏左副标题改为“双屏模式下的大屏左输出”。
- 移动端“系统静音”缩为“静音”，避免顶栏换行。
- 媒体源行菜单、背景音乐图标按钮与 switch 增加动态可读名称。
- Naive UI Slider 的可聚焦 handle 不继承根节点 `aria-label`，已增加专用指令并在 D2 部署后复核通过。

### 4.6 账户页缺少注销入口

- **表现**：鉴权 Store、注销 API 和文案均存在，但账户页只能修改密码，用户无法从 UI 注销。
- **修复**：账户页增加“当前会话”卡片和“退出登录”按钮；成功后清理会话并跳转登录页。
- **实机结论**：移动端按钮可见，注销 200，业务页鉴权恢复正常。

### 4.7 Danger 对话框没有安全取消路径

- **表现**：打开关闭服务、删除、清空列表等危险确认后，仅有红色确认按钮；Esc、遮罩和关闭按钮也被禁用。
- **根因**：全局 Dialog 把“是否允许 Esc/遮罩关闭”和“是否显示取消按钮”错误合并为同一个 `cancellable` 条件。
- **修复**：危险对话框继续禁止 Esc/遮罩误关，但始终显示明确“取消”按钮。
- **实机结论**：关服和删除确认均可取消；取消后服务与测试源保持不变。

### 4.8 多 PPT 并行时关闭一路后无法重新打开

- **测试方法**：使用两个独立 Playwright 页面分别控制大屏左、右；窗口 1 打开 `TestPPT`，窗口 2 打开 `AllinOne`，分别翻到 2/7、3/9；关闭窗口 1，保持窗口 2 放映，再从前端重新打开窗口 1。
- **修复前表现**：首次并行、独立翻页和单侧关闭均正常；窗口 1 重开时进入 error，错误为 `PowerPoint.Application.Presentations`，窗口 2 仍稳定保持 3/9。
- **根因**：窗口 1 关闭后自动重建 PowerPoint 应用级预热；PowerPoint 为进程级 COM 服务器，另一窗口仍在放映时新得到的预热 `Application` 代理可能已被 Office 断开。适配器接管该代理前没有验证，访问 `Presentations` 时直接失败。
- **修复**：接管预热 PowerPoint `Application` 时先读取 `Presentations` 验证代理；失效代理立即退休，并通过新的 `DispatchEx` 重新连接。
- **自动验证**：新增“失效预热 Application 自动重连”回归用例；全量 `370 passed`，Django check 与 Ruff 通过。
- **修复后实机结论**：日志明确记录“预热 PowerPoint COM 应用已失效，重新创建”，随后窗口 1 在约 1.5 秒内成功重开；窗口 2 全程保持 AllinOne 3/9。继续完成单侧 PPT→PPT、同一 PPT 两窗口独立页码和分别关闭，均通过。
