# SCP-cv 使用文档

本文面向 28#108 现场部署、值守和调试人员，说明 SCP-cv 的安装、配置、启动、播控流程和常见故障处理方式。

## 1. 系统说明

SCP-cv 用于控制上海第二工业大学 28#108 多媒体显示系统。系统由五类进程协作：

| 进程 | 作用 |
|------|------|
| Vue 控制台 | 浏览器播控界面，运行在 `frontend/` |
| Django 服务端 | REST、SSE、gRPC、媒体文件、播放会话状态和持久化控制命令队列 |
| PySide6 播放器 | 本机播放窗口和后台音频播放器，负责视频、图片、网页、SRT 显示、背景音乐输出及 PPT 嵌入容器 |
| PowerPoint Broker | 当前用户 Session 中唯一的 PPT COM 协调进程；通过单一 STA 和单一 PowerPoint Application 管理 PNG/播放缓存导出、预热及窗口 1-4 放映 |
| MediaMTX | SRT 推流接收与读取服务 |

播放控制统一在 Web 控制台完成。本机播放器只负责创建输出窗口并执行后端下发的播放指令。

## 2. 环境准备

### 2.1 基础软件

- Windows 10/11
- Python 3.12+
- Node.js 20+
- Microsoft PowerPoint（唯一支持的 PPT 播放、预览和导出组件）
- VLC/libVLC Windows x64 runtime
- MediaMTX Windows x64

### 2.2 安装依赖

```powershell
cd E:\Projects\SCP-cv

uv python install
uv sync

npm ci --prefix frontend
```

项目依赖以 `pyproject.toml`、`uv.lock`、`frontend/package.json` 和 `frontend/package-lock.json` 为准，不再维护 `requirements*.txt`。

### 2.3 准备第三方运行时

MediaMTX：

```text
tools/third_party/mediamtx/mediamtx.exe
tools/third_party/mediamtx/mediamtx.yml
```

VLC/libVLC 满足以下任一条件即可：

- 系统安装 Windows x64 VLC，默认路径 `C:\Program Files\VideoLAN\VLC`
- 将 Windows x64 VLC zip 包解压到 `tools/third_party/vlc/runtime/`

SRT 播放至少需要：

```text
tools/third_party/vlc/runtime/libvlc.dll
tools/third_party/vlc/runtime/libvlccore.dll
tools/third_party/vlc/runtime/plugins/access/libaccess_srt_plugin.dll
```

Microsoft PowerPoint 需要安装在当前 Windows 用户可自动化调用的桌面会话中；若 COM 自动化失败，先在该用户桌面会话中手动打开 PowerPoint 并确认可以打开目标 PPT。现场播放时由 PowerPoint Broker 统一管理持续运行的 COM Application，播放器进程不会各自启动 PowerPoint。

PPT 配置说明：

- PowerPoint 是唯一 PPT 播放器；导入、预览、播放缓存、预热和放映均不再提供后端选择。
- 支持 `.pptx/.ppt/.pps/.ppsx/.pptm/.ppsm/.pot/.potx/.potm/.odp` 等演示文件。导入后会尝试生成播放专用 `.ppsx`/`.pps` 缓存，宏格式默认导出为非宏 `.ppsx`；生成失败不阻断媒体源创建，播放时回退原始文件。
- 当前 Windows 用户和 Session 只运行一个 PowerPoint Broker。Broker 内部只有一个 COM STA，并懒加载一个供 PNG 预览导出、`.ppsx`/`.pps` 缓存导出、预热和窗口 1-4 放映共同使用的 PowerPoint Application；播放器只提交请求和提供嵌入容器 HWND。
- PPT 媒体源启用预热后，由 Broker 以低优先级按 `source_id + uri` 进行文件级预热；前台打开、关闭和翻页会优先执行，命中时认领预打开的 Presentation。
- PPT 放映时目标 PySide 播放窗口会立即切到黑色视频容器并保持可见、置顶。Broker 保留完整放映范围，启动窗口化放映后对非首页目标显式跳页；验证 `SlideShowWindow.HWND` 后，按“放映窗口 → Broker 原生 host → Player 视频容器”的两级父链嵌入。
- PPT 切换采用事务式替换：新放映和嵌入验证成功后才释放旧 Presentation，失败时恢复旧画面。
- 关闭前 Broker 会先隐藏放映、把中间 host 从 Player 父链脱离、将放映 HWND 恢复为隐藏顶层窗口并销毁 host；随后退出 View、释放放映 HWND 并关闭对应源 Presentation。最后一个公开会话关闭前会创建一个无窗口、无 SlideShowWindow、未注册为会话的空白 Application sentinel，使同一 Application 后续仍可重新放映；sentinel 仅在 Broker shutdown 时关闭。
- 开发模式下可拖动调整 Player 窗口尺寸；尺寸稳定后会通过 AF_PIPE 通知 Broker，同步调整中间 host 和放映窗口。生产模式仍固定为目标显示器全尺寸。
- 右上角“应急控制 → 重置 PPT 放映”会为各窗口提交持久化关闭和重开批次，并恢复到重置前页码。
- PNG 预览和 `.ppsx`/`.pps` 播放缓存导出也通过同一 Broker/STA/Application 执行；任务结束后只关闭临时 Presentation，不影响活动放映会话。
- `PPT_PREVIEW_WORKER_TIMEOUT_SECONDS`：保留旧配置名，现用于限制 Broker PNG 预览导出调用的等待时间；失败或超时只影响缩略图，不影响媒体源创建。
- `PPT_PLAYBACK_EXPORT_TIMEOUT_SECONDS`：限制 Broker 生成 `.ppsx`/`.pps` 播放缓存的等待时间；失败或超时只记录 metadata 并回退原始文件播放。

播放器和 Broker 使用当前用户 Session 专属的 Windows `AF_PIPE` 通信。Broker 将管道地址、PID 和代次写入 `%LOCALAPPDATA%\SCP-cv\runtime\ppt-broker.json`，认证密钥写入同目录的 `ppt-broker.auth`；诊断元数据不包含密钥，不要把认证文件复制到其它主机或提交到仓库。

Broker 创建 PowerPoint 前后会记录 `POWERPNT.EXE` 的 PID 和创建时间，优先按 Application 窗口定位进程，无法定位时只接受启动后唯一新增的 PID；只有该 PID 不在启动前快照中才视为自有进程。退出时先确认没有外部文档；只有 `Quit()` 失败且 PID、创建时间、进程名和无顶层窗口都能再次确认时，才允许精确清理。无法确认时保留进程，因此不要手工结束未知的 `POWERPNT.EXE`。

直播低延迟配置说明：

- `MEDIAMTX_SRT_PUBLISH_LATENCY_US` 控制推流端 URL 的 SRT latency，单位为微秒；`MEDIAMTX_SRT_READ_LATENCY_MS` 控制播放器拉流 URL 的 SRT latency，单位为毫秒。
- `STREAM_VLC_NETWORK_CACHING_MS`、`STREAM_VLC_LIVE_CACHING_MS`、`STREAM_VLC_FILE_CACHING_MS` 控制前台 libVLC 缓存；现场网络抖动明显时可适当增大。
- `STREAM_VLC_CLOCK_JITTER`、`STREAM_VLC_CLOCK_SYNCHRO`、`STREAM_VLC_DROP_LATE_FRAMES`、`STREAM_VLC_SKIP_FRAMES` 控制播放器追实时策略；低延迟优先时保持默认值。
- `STREAM_PREHEAT_NETWORK_CACHING_MS`、`STREAM_PREHEAT_LIVE_CACHING_MS`、`STREAM_PREHEAT_TTL_SECONDS` 控制直播 URI 级可认领预热连接。

`frontend/.env` 管理 Vite 控制台：


现场局域网访问时，`VITE_BACKEND_TARGET` 必须写成浏览器可直连的后端地址，例如 `http://192.168.1.100:8000`。`runall` 会移除父进程继承的 `VITE_*` 变量，避免根目录 `.env` 或系统环境变量遮蔽 `frontend/.env`。

## 3. 启动系统

### 3.1 一键启动

```powershell
uv run python manage.py runall
```

常用参数：

```powershell
# 局域网访问
uv run python manage.py runall --backend-host 0.0.0.0 --frontend-host 0.0.0.0

# 跳过已外部启动的 MediaMTX
uv run python manage.py runall --skip-mediamtx

# 调试时跳过播放器或前端
uv run python manage.py runall --skip-player
uv run python manage.py runall --skip-frontend

# 自定义前端端口；未指定时读取 frontend/.env
uv run python manage.py runall --frontend-port 5174

# 纯命令行模式：跳过播放器启动器 GUI，直接按显示器 ID 创建 4 个窗口
uv run python manage.py runall --headless

# 后台模式：脱离当前终端生命周期，输出写入 logs/runall/service/
uv run python manage.py runall --headless --service

# 指定窗口到 Windows 显示器 ID，并指定 GPU ID
uv run python manage.py runall --headless --window1 1 --window2 2 --window3 3 --window4 4 --gpu 0
```

`--headless` 会自动启动 MediaMTX、Django、Vue 前端和 PySide6 播放器，不再弹出显示器选择 GUI。未显式指定 `--window1`、`--window2`、`--window3`、`--window4` 时，窗口 1-4 默认映射到 Windows 显示器 ID 1-4；每个窗口使用独立 PySide 播放器进程隔离 Qt 和渲染生命周期，PPT 则统一交给同一个 Broker。`runall` 会复用当前 Windows Session 中健康的 Broker，否则启动自有实例；它持续校验 PID + generation，并等待 AF_PIPE 就绪后才启动播放器。停止时先关闭播放器；只有自有 Broker 才发送 `shutdown` 并等待，复用 Broker 不取得关闭所有权，Broker 不走递归 PowerPoint 进程树终止。`--skip-player` 同时跳过 Broker；该模式若仍需导入 PPT 并生成 PNG/播放缓存，需单独启动 `run_ppt_broker`。`--window3` 兼容别名 `--windows3`。未显式指定 `--gpu` 时，播放器不强制选择显卡，使用系统默认 GPU。

通过 SSH 或 OpenSSH 服务远程启动时，当前进程通常位于 Windows Session 0，只能看到服务会话虚拟屏，无法直接使用控制台桌面的 4 个物理显示器。此场景请使用 `uv run python manage.py runall --headless --service`，后台启动器会把真实 runall 转交给当前登录用户的交互桌面运行；若在 D2 控制台桌面本地操作，则可直接运行 `--headless`。

启动完成后：

1. 浏览器打开 `http://127.0.0.1:5173/`。
2. 手机或其它局域网设备打开 `http://<主机局域网IP>:5173/`。
3. 在播放器启动器中选择 SRT 渲染显卡和显示目标；若使用 `--headless`，则按命令行参数或默认显示器 ID 自动创建窗口。
4. 在 Web 控制台添加或选择媒体源并打开到指定窗口。

### 3.2 分进程启动

```powershell
# 终端 1：Django
uv run python manage.py runserver

# 终端 2：Vue
npm --prefix frontend run dev

# 终端 3：PowerPoint Broker（显式分进程调试时先启动）
uv run python manage.py run_ppt_broker

# 终端 4：播放器
uv run python manage.py run_player

# 终端 4：播放器无 GUI 启动
uv run python manage.py run_player --headless --window1 1 --window2 2 --window3 3 --window4 4

# 单窗口调试，常用于验证某一路 PPT/显示器
uv run python manage.py run_player --headless --only-window 2 --window2 2

# 终端 5：MediaMTX
.\tools\third_party\mediamtx\mediamtx.exe .\tools\third_party\mediamtx\mediamtx.yml
```

普通独立 `run_player` 会先连接当前用户 Session 中健康的 Broker；若不存在，会自行启动 `manage.py run_ppt_broker`，并只在自己拥有该子进程时于退出阶段关闭它。`--only-window` 不会自行启动 Broker，单独调试该模式前必须先运行 `run_ppt_broker`，否则命令会直接说明缺少 Broker。

### 3.3 清除运行数据

如需恢复到空数据库、空媒体和空日志状态，先停止 `runall`、Django、所有播放器和 PowerPoint Broker 等进程，再执行：

```powershell
uv run python manage.py clearall
```

`clearall` 会删除 `db.sqlite3`、`db.sqlite3-journal`、`db.sqlite3-wal`、`db.sqlite3-shm`，清空 `media/` 和 `logs/`，重新执行迁移，并只按 `config.toml` 写入固定数据。当前固定数据仅包含默认管理员账号；若要修改默认管理员，请先编辑根目录 `config.toml`。

## 4. 控制台操作

### 4.1 页面入口

| 页面 | 用途 |
|------|------|
| 总览 | 查看系统状态、大屏模式、系统音量、设备电源 |
| 大屏左 / 大屏右 / TV 左 / TV 右 | 对指定窗口打开源、关闭显示、控制播放 |
| 背景音乐 | 管理音频源播放列表、立即播放、循环、音量和静音 |
| 媒体源 | 上传文件、添加网页源、本机路径和直播源，管理源列表 |
| 播放控制 | 四窗口播放、PPT 翻页、视频 Seek、窗口音量和循环 |
| 预案管理 | 保存四窗口组合，在列表中直接调用、置顶或取消置顶，一键恢复现场场景 |
| 系统设置 | 显示器目标、设备电源、运行态和开发信息 |

### 4.2 添加媒体源

- 上传文件：支持 PPT、视频、图片、音频等常用格式。
- 临时上传即开：上传后直接打开到当前窗口，关闭或切换后清理临时源。
- 本机路径：适合不需要上传的大文件，例如 `D:\Videos\demo.mp4`。
- 网页源：填写 URL，可作为网页看板或局域网页面打开。
- 预热：窗口媒体源可开启预热；播放器负责图片、视频、网页、背景音频和直播资源，PowerPoint Broker 负责 PPT 文件级预热，现场切换时按 `source_id + uri` 优先认领。SRT/RTSP/自定义直播复用 URI 级 libVLC 连接；音频源不占用四个播放窗口，由背景音乐通道播放。
- SRT 直播：外部设备推流到 `srt://<主机IP>:8890?streamid=publish:<流标识>&latency=30000&pkt_size=1316` 后，系统会同步为直播源；自动发现源默认使用 MediaMTX 自动暴露的 `rtsp://<主机IP>:8554/<流标识>` 作为播放器拉流地址。
- 推流端低延迟建议：H.264、CBR/CFR、关键帧间隔约 1 秒、关闭 B 帧和 lookahead；x264 可使用 `tune=zerolatency`，NVENC 可选择低延迟预设。网络抖动明显时优先增大 SRT/read/VLC 缓存，而不是让播放器无限追帧。

### 4.3 播放与控制

1. 进入对应显示控制页。
2. 选择媒体源，点击打开源。
3. 按源类型使用对应控制：
   - PPT：上一动画/页、下一动画/页、跳页、页面媒体播放/暂停、专注模式；专注模式横屏下支持左侧缩略图跳页。
   - 视频：播放、暂停、停止、进度条、循环、窗口音量。
   - 图片/网页：打开、关闭、切换源。
   - 直播：查看在线状态和拉流地址，必要时重新打开源。
4. 关闭显示时，后端把关闭指令写入目标窗口的持久化队列；播放器确认关闭完成后，会话才稳定进入空闲态。

控制动作会先写入持久化 `ControlCommand` 队列。窗口 1-4 与背景音频各有独立顺序通道；播放器原子领取最早的待执行指令，并在完成后确认成功、失败或取消。下发接口返回只表示指令已被接受，最终结果以 SSE 会话状态和命令终态为准。每个消费者用 `consumer_id + PID + 进程创建时间` 标识并持续续约心跳；恢复流程只终结进程已消失、身份不匹配或租约过期的执行记录，不会误清理仍存活的播放器。被恢复的指令标记失败且不盲目重放，尚未领取的指令继续保留；旧 `pending_command` 字段仅用于兼容显示。

### 4.4 背景音乐

1. 在“媒体源”页上传或添加音频源，或进入“背景音乐”页从音频源列表选择。
2. 点击“立即播放”会自动加入背景音乐列表并下发到本机播放器进程播放。
3. 点击“加入列表”只维护播放列表，不会影响当前播放。
4. 背景音乐页可控制播放、暂停、停止、上一首、下一首、循环、静音和音量。
5. 删除当前播放的列表项或清空播放列表时，系统会自动停止背景音乐并清空当前音频源。

### 4.5 大屏模式

- `single`：只使用大屏左，窗口 2 自动隐藏并静音。
- `double`：大屏左和大屏右分别对应窗口 1/2。
- TV 左 / TV 右：分别对应窗口 3/4，默认静音。

显示器目标在系统设置页应用。现场调整 Windows 显示设置后，建议重新启动播放器。

### 4.6 设备电源和音量

控制台提供拼接屏、TV 左、TV 右电源按钮。设备指令通过 TCP 发送，不读取设备返回状态。系统音量优先调用 Windows Core Audio；若当前环境无法同步系统音频设备，接口会返回 `system_synced=false`。

## 5. 接口和集成

REST API 的机器可读合同位于：

```text
docs/openapi.yaml
```

该文件是多文件 OpenAPI 入口，具体路径和组件拆分在 `docs/paths/` 与 `docs/components/`；需要单文件分发时使用已生成的 `docs/_bundled.yaml`，或执行 `npx @redocly/cli bundle docs/openapi.yaml --output docs/_bundled.yaml` 重新生成。

gRPC 合同位于：

```text
protos/scp_cv/v1/control.proto
```

gRPC 的 `PlaybackControlService` 保留给中控系统和自动化脚本使用，覆盖播放控制、状态查询、显示器查询、预案管理和媒体源管理。媒体源列表与新增/更新响应中的 `SourceItem` 字段与 REST 媒体源 payload 对齐，包含 `metadata`、文件属性、`keep_alive`、`preheat_enabled`、`preview_url`、`thumbnail_url`、`preview_kind` 和 `preview_label`。`UpdateSource` 仅允许更新显示名称、网页源 URL 和媒体预热开关；文件型源路径仍通过重新上传或重新注册管理。

`GetRuntimeStatus.grpc_endpoint` 返回客户端可直接连接的地址。若服务监听配置为 `0.0.0.0` 或 `::`，状态响应会展示为 `127.0.0.1:<GRPC_PORT>`，避免外部脚本拿到不可连接的 wildcard 地址。

默认服务信息：

| 服务 | 地址 |
|------|------|
| REST / SSE | `http://127.0.0.1:8000/` |
| gRPC | `127.0.0.1:50051` |
| PowerPoint Broker | 当前用户 Session 专属 Windows `AF_PIPE`，诊断元数据位于 `%LOCALAPPDATA%\SCP-cv\runtime\ppt-broker.json` |
| MediaMTX API | `http://127.0.0.1:9997/` |
| SRT publish | `srt://<主机IP>:8890?streamid=publish:<流标识>&latency=30000&pkt_size=1316` |
| RTSP read | `rtsp://127.0.0.1:8554/<流标识>` |

### 6.1 四窗口 PPT 并发物理冒烟

该命令会替换 Broker 中窗口 1-4 的现有 PPT 会话，并在桌面创建窗口，属于侵入式现场诊断；不要在正式播放期间执行。先启动 `runall` 或单独运行 `uv run python manage.py run_ppt_broker`，再从媒体源列表取得 PPT source ID。四窗复用同一源时，该 PPT 至少需要 5 页：

```powershell
uv run python manage.py ppt_smoke --windows 1,2,3,4 --source-ids 42 --iterations 3 --timeout 120
```

`--source-ids` 可以只给一个 ID 供四窗复用，也可以按 `--windows` 顺序给四个 ID，例如 `42,43,44,45`。命令会在连接 Broker 前拒绝空项、数量不符、不存在、非 PPT、不可用或文件已丢失的源。它会自动创建四个临时 PySide 宿主并保持 GUI 消息循环，不会用“最大窗口”等方式猜测父 HWND。

旧的路径型 `run_ppt_physical_smoke` 命令继续兼容；需要对已有原生容器做定向诊断时，可以四项全部提供，HWND 支持十进制或 `0x` 十六进制。只填写其中一部分会直接报错。

```powershell
uv run python manage.py run_ppt_physical_smoke `
  --ppt "D:\Slides\smoke.pptx" `
  --window1-hwnd 0x10101 --window2-hwnd 0x10102 `
  --window3-hwnd 0x10103 --window4-hwnd 0x10104 `
  --iterations 3 --broker-timeout 120
```

每轮会从四个调用线程同时提交 OPEN，并检查以下不变量：

- 四个放映 HWND 均非零且互不重复。
- Broker 状态记录对应 Player 容器，Win32 父链必须是“放映窗口 → Broker host → Player 容器”；兼容环境没有中间 host 时允许放映窗口直接指向 Player 容器。
- 窗口 1-4 分别跳到第 2/3/4/5 页时，其它窗口页码、HWND 和父链不变。
- 每轮轮换关闭一个窗口后，其余三个窗口的页码、HWND 和父链不变；随后重开被关闭窗口并再次验证四窗唯一 HWND、父链和各自页码。
- `finally` 能幂等清理本轮全部 owner 会话；任何清理错误同样判定失败。

命令输出 JSON，顶层包含 `success`、`source_ids`、`ppt_paths`、窗口、请求/完成轮数、Broker PID/代次和 `rounds`；每轮还包含不同页码、被关闭窗口、存活窗口、重开 HWND、最终页码和清理错误。验证失败时先输出 JSON，再以非零退出码结束；Broker、PowerPoint、交互桌面、PPT 页数或显式父 HWND 配置错误也会给出明确处置提示。现有 `POST /api/playback/physical-smoke/` 仍用于数据库播放器链路的逐类媒体回归，不具备此命令的 Broker owner 和真实 HWND 并发校验。

## 7. 常见问题

### 7.1 前端 `.env` 修改后不生效

确认修改的是 `frontend/.env`，不是根目录 `.env`。修改后重启 Vite 或 `runall`。`runall` 已在启动前端时清理父进程中的 `VITE_*`，避免后端 `.env` 读入的变量覆盖前端配置。

### 7.2 手机能打开前端但接口失败

把 `frontend/.env` 中的 `VITE_BACKEND_TARGET` 改为手机可访问的后端地址，例如 `http://192.168.1.100:8000`，并用 `--backend-host 0.0.0.0` 启动后端。

### 7.3 SRT 直播无法播放

1. 打开 `http://127.0.0.1:9997/v3/paths/list` 检查 MediaMTX。
2. 检查 OBS 推流 URL 是否为 `srt://<主机IP>:8890?streamid=publish:<流标识>&latency=30000&pkt_size=1316`，且不要使用 `rtmp://`、`:9997` 或 `127.0.0.1`（除非 OBS 与 MediaMTX 在同一台机器）。
3. 检查 VLC runtime 是否包含 `libvlccore.dll` 和 `plugins/access/libaccess_srt_plugin.dll`。
4. 查看 `logs/app/scp-cv.log` 与最新 `logs/runall/<启动时间>/mediamtx.log`。

### 7.4 PPT 不能播放

确认本机安装了 Microsoft PowerPoint，并且当前 Windows 用户可以正常打开目标 PPT 文件。检查最新 `logs/runall/<启动时间>/powerpoint-broker.log`，以及 `%LOCALAPPDATA%\SCP-cv\runtime\ppt-broker.json` 中的 Broker PID、代次和管道地址；四个播放器日志应连接同一个 Broker PID，而不是各自出现 PowerPoint COM 实例。继续核对每个活动窗口是否拥有唯一放映 HWND，Win32 父链是否为“放映窗口 → Broker host → 目标 PySide 容器”。关闭最后一个外部会话后，共享 PowerPoint PID 和无窗口 sentinel Presentation 可继续存活到 Broker shutdown，但公开会话必须不可查询且不得保留 SlideShowWindow；PowerPoint 可能把旧数值 HWND 复用为标题仅为 `PowerPoint` 的 Application frame，这不属于放映残留。若放映窗口卡住，可使用右上角“重置 PPT 放映”关闭并重开当前窗口放映；不要手工结束未知 `POWERPNT.EXE`。

### 7.5 `--service` 启动后如何查看状态

`--service` 会立即返回当前终端，后台拉起日志写入 `logs/runall/service/runall-service-<时间>.log`。真实 runall 启动后，各子进程日志写入 `logs/runall/<启动时间>/mediamtx.log`、`django.log`、`vue-前端.log`、`powerpoint-broker.log`、`pyside-播放器-1.log` 到 `pyside-播放器-4.log` 等对应文件。Broker 是 required 依赖：readiness 超时、断开或 PID + generation 被替换会触发整组清理。需要停止后台服务时，优先在 Web 控制台触发系统关闭；runall 会先停止播放器，只对自己启动的 Broker 发送 `shutdown`，复用的 Broker 保持运行。

### 7.6 拼接模式不可用

确认 Windows 已识别至少两台显示器，显示模式为“扩展”而不是“复制”。调整显示器后重启播放器。
