# Feature Specification: 共享多端控制台与Windows播控重构

**Feature Branch**: `refactor/003-dotnet-runtime`

**Created**: 2026-09-08

**Status**: Implementation / 规范与设计已完成，按 `tasks.md` 从 Phase 1 开始实施

**Input**: 用户要求采用 Vue 3 控制台、ASP.NET Core ControlHost、SQLite/EF Core、持久命令队列、Named Pipe、交互桌面 Supervisor、四个 WPF PlayerWorker、独立 AudioWorker、唯一 STA/COM PowerPointHost 和 MediaMTX 对本仓库进行重构规划；保持现有 REST/SSE 合同与核心逻辑。指定技术选择记录于 [plan.md](./plan.md)，下文定义与技术实现无关的验收行为。

**Scope Update**: 用户明确当前处于快速迭代期、没有现场维护需求，版本恢复依靠Git，不设计复杂生产迁移/回滚。共享前端改为Vue 3 + Tailwind CSS 4 + Vue Router + Pinia + Vite；网页直接使用，Windows客户端使用Electron，Android客户端使用Capacitor。播放器运行时仍在Windows，Linux/macOS原生客户端不在本次范围。

## Clarifications

### Session 2026-09-08

- Q: Android客户端可以采用Capacitor封装同一套Vue页面吗？ → A: 可以。Android使用Capacitor，Windows使用Electron，与网页共享Vue页面与业务逻辑。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在网页、桌面与手机使用同一套控制台 (Priority: P1)

用户通过网页、Windows客户端、Android客户端使用相同的页面、导航和业务操作，登录、管理媒体、操作四窗口、切换大屏模式、使用预案和控制设备。界面样式与封装可以调整，业务规则保持。

**Why this priority**: 本次是等价重构，不能以替换底层为由删除或悄悄改变现有能力。

**Independent Test**: 三端连接同一测试主机，用同一组测试账户和媒体完成相同流程；验证共享页面、状态与权限一致，而不是只验证三个空壳能启动。

**Acceptance Scenarios**:

1. **Given** 测试主机上有效账户和媒体，**When** 分别从网页、Windows和Android登录，**Then** 三端看到相同业务状态，权限一致；各端登录会话独立，不要求共享Cookie文件。
2. **Given** 四个窗口及单/双大屏模式，**When** 操作打开、关闭、静音和模式切换，**Then** 窗口编号、固定静音策略和一个窗口对应一个显示器的含义不变。
3. **Given** 预案含未设置、清空、指定源三种状态，**When** 激活，**Then** 未设置窗口不变、清空窗口停止显示、指定窗口打开原绑定源；音量和模式的三态沿用旧规则。
4. **Given** 一项该媒体不支持的动作，**When** 从控制台或外部调用发起，**Then** 得到明确拒绝，界面不伪造成功；控制链路在线与播放器在线分别展示。
5. **Given** Android客户端选择手机文件，**When** 上传，**Then** 向播放主机上传文件内容；“添加本机路径”仍明确指播放主机路径，不误把手机路径发送为可播放文件。

### User Story 2 - 连续指令和故障恢复不会造成误操作 (Priority: P1)

操作人员快速翻页、调音量和切源时，系统保持原有顺序与合并规则；故障后不会悄悄丢指令或重放危险动作。

**Why this priority**: 播控是否真实执行关系到现场可预测性，网络连接成功不等于显示成功。

**Independent Test**: 在领取前后、实际执行前后、确认前后注入断连、崩溃和迟到结果，比较可观察状态与命令处理结果。

**Acceptance Scenarios**:

1. **Given** 已接收但未实际执行的有效指令，**When** 执行端退出后恢复，**Then** 指令保留并按有效顺序恢复，不被旧执行端结果覆盖。
2. **Given** 已执行但确认结果丢失的相对翻页或设备切换动作，**When** 重连，**Then** 优先核对真实状态；无法确定时报告待人工处理，不盲目重复动作。
3. **Given** 正在打开 A、随后打开 B、再打开 A，**When** 老的加载结果迟到，**Then** 不覆盖最新请求的源、预览、放映模式或错误。
4. **Given** 调音量和终止类命令穿插，**When** 排队，**Then** 保留既有合并与取代规则；后台音频不套用显示窗口的终止取代规则。

### User Story 3 - 演示文稿保持原放映质量与回退规则 (Priority: P1)

需要动态效果的演示文稿仍使用原生放映，其他演示文稿使用版本匹配的静态回退，导入后的预览、备注和页内媒体控制仍可用。

**Why this priority**: 动画、页内媒体、翻页和多窗口共存是项目区别于普通视频播放器的核心能力。

**Independent Test**: 同时在四窗口打开演示文稿，并在放映期间导入另一个文稿；检查唯一动态放映、静态回退、页码和失败表现。

**Acceptance Scenarios**:

1. **Given** 无活动动态放映，**When** 打开允许原生播放的文稿，**Then** 获得唯一槽位；其余窗口不启动第二个动态放映。
2. **Given** 槽位被占用，**When** 打开另一文稿，**Then** 使用源版本匹配的静态回退；缺失或过期则明确失败，并尽可能保留原画面。
3. **Given** 已使用静态回退，**When** 槽位释放或操作全局动态放映重置，**Then** 不自动升级、不重开该静态窗口。
4. **Given** 正在动态放映，**When** 导入文件需要生成预览或缓存，**Then** 不争抢放映、不额外创建竞争实例；准备延后或失败可诊断且不阻断源注册。

### User Story 4 - 保持网页状态和低等待切换 (Priority: P1)

已预热网页切离后保持登录、滚动和脚本状态，再切入不重新导航；视频、图片和直播复用有效资源。

**Why this priority**: 现场重复冷加载会造成黑屏和登录状态丢失。

**Independent Test**: 在同一输出窗口反复切换两页带计数器的网页，测量导航次数；直播持续预热后再切入。

**Acceptance Scenarios**:

1. **Given** 同一窗口内已预热且未损坏的页面，**When** 连续切入切出 50 次，**Then** 页面实例不更换，导航次数不增加，登录、滚动和脚本状态保持。
2. **Given** 持续预热直播，**When** 10 分钟后切入，**Then** 使用仍有效的连接或提前续热的新连接，不因固定时长直接冷启动。
3. **Given** 文件已替换或安全上下文发生变化，**When** 请求旧缓存，**Then** 不误认领旧版本；新源准备失败时保留旧画面或进入可诊断安全态。

### User Story 5 - 独立音频与可诊断开发运行 (Priority: P2)

开发者和用户可启动、停止、重启并查看错误；背景音乐保持独立。实际多屏播放只在Windows主机的正确交互桌面执行，关闭控制台客户端不等于停止播放主机。

**Why this priority**: 重构不能增加日常使用负担，也不能用后台服务在线假装物理画面在线。

**Independent Test**: 在隔离桌面验证后台音频播放列表、一次完整启停、窗口退出和无交互桌面场景。

**Acceptance Scenarios**:

1. **Given** 背景音乐播放列表，**When** 立即播放、上一首/下一首、自然结束、循环、删除当前项和静音，**Then** 与原流程一致，不占用显示窗口。
2. **Given** 用户请求整组退出或一个输出进程退出，**When** 按默认兼容策略停止，**Then** 先协作清理，再对明确超时的项目自有进程强制退出；不误杀用户软件。
3. **Given** 没有可用交互桌面，**When** 启动，**Then** 明确报告无法进行物理播放，不显示虚假的播放器在线；恢复桌面后由明确启动/恢复动作接管。

### User Story 6 - 通过版本管理快速迭代 (Priority: P2)

开发者按小步提交替换模块，依靠源码版本管理比较和撤销代码变更。当前没有现场维护负担，不需要生产数据转换、双版本并行部署或反向数据同步工程。

**Why this priority**: 项目仍在快速迭代，应将成本投入核心功能和三端验证，而不是尚不存在的现场升级流程。

**Independent Test**: 在新建测试数据目录初始化当前版本并运行核心回归；检查代码变更可定位至独立提交，且没有隐式清空现有数据的脚本。

**Acceptance Scenarios**:

1. **Given** 一个新测试目录，**When** 初始化新后端，**Then** 可建立测试账户与样例数据，不依赖从旧数据库导入。
2. **Given** 一个有问题的代码改动，**When** 通过版本管理撤销，**Then** 只恢复受跟踪源码、规范和锁文件，不声称恢复未跟踪数据库或媒体。
3. **Given** 磁盘已有用户数据，**When** 切代码版本或重建测试环境，**Then** 不自动删除、覆盖该数据；不兼容数据可另选新目录，清空必须单独明确授权。

### Edge Cases

- 管道唤醒丢失、数据库写入失败、执行端卡住但进程仍活着、旧租约确认迟到。
- 新旧进程同时启动或同一用户的两个桌面会话竞争同一输出、音频、Office。
- 网页渲染进程崩溃；静态缓存损坏；预热达到资源预算；同一源在两个窗口同时展示。
- 切换分辨率、拔插显示器、混合缩放比例、远程连接改变交互会话、Office 弹出模态对话框。
- 音频自然结束通知重复，或旧源结束通知晚于新源播放。
- 已登录控制台切换服务器、过期会话、过期防伪令牌、Android退后台/断网后回前台。
- 新后端选到旧格式数据库，或源文件位于允许媒体目录之外；提示不兼容/拒绝访问，不自动破坏数据。
- 媒体导入失败后的半成品、切源后仍被预热页面/播放器引用的临时文件。
- 打包后路由刷新/返回键、上传取消、下载权限、设备WebView过旧或后端证书不可信。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 由同一套共享前端实现网页、Windows、Android控制台的业务页面、路由、状态与操作；可以调整样式和平台适配，保留认证、媒体、显示、预案、设备、系统及实时状态的外部合同。
- **FR-002**: MUST 保留用户名密码登录、账户权限、改密后当前会话可用、未授权拒绝与跨站请求保护；新测试库可重新初始化账户，不要求搬迁旧账户哈希或旧会话。
- **FR-003**: MUST 保留媒体源类型、API标识语义、文件夹、上传/播放主机路径/网页/流录入、下载预览与临时源生命周期；不要求历史记录ID跨新旧数据库迁移保持一致。
- **FR-004**: MUST 保留窗口 1–4 语义、单/双大屏模式、固定静音策略及单窗口单显示器选择；不恢复已移除的跨屏拼接。
- **FR-005**: MUST 保留预案三态、排序置顶、捕获与激活语义，以及全部现有设备指令和系统音量行为。
- **FR-006**: MUST 保留独立背景音乐的播放列表顺序、自然结束推进、循环、定位、音量、静音和删除源行为。
- **FR-007**: MUST 在指令接收后保留可恢复记录，按目标顺序执行，仅在收到真实完成或明确失败结果后结束该次处理。
- **FR-008**: MUST 保留显示指令合并/取代和背景音频有序处理的区别，不用一个可覆盖槽位替代持久队列。
- **FR-009**: MUST 拒绝失去所有权的执行端回写；对重复投递提供去重/真实状态核对；不确定的非幂等动作不得自动重复。
- **FR-010**: MUST 保留来源实际状态与控制意图区分，播放模式、错误、页码与进度仅由有效执行结果确认，迟到结果不得覆盖新请求。
- **FR-011**: MUST 保留各媒体能力限制、PPT 实际放映模式、只重置动态放映窗口、前端快速切源竞态防护。
- **FR-012**: MUST 保持全主机最多一个本系统动态演示文稿放映所有者；未释放旧实例时不创建竞争实例。
- **FR-013**: MUST 保留匹配源版本的静态回退、回退缺失安全失败、回退后不自动升级规则。
- **FR-014**: MUST 保留导入、预览、备注、页内媒体资源、播放缓存和动态翻页能力；后台资源准备不得干扰活动放映。
- **FR-015**: MUST 对健康且已接受预热的同窗口网页保留实例状态，切换仅改变可见资源，不重新导航。
- **FR-016**: MUST 按源版本、窗口与安全上下文管理预热、认领、归还、健康检查和退出清理；不能把不可跨进程对象描述为全局可移动缓存。
- **FR-017**: MUST 保留直播自动发现、在线状态、推拉流地址和现场参数语义，并持续检查预热连接有效性。
- **FR-018**: MUST 保留协作退出、明确超时、安全重置和项目自有资源清理；默认仍采用任一输出进程退出后整组协作停止的兼容策略。
- **FR-019**: MUST 在正确用户交互桌面执行播放、Office 与音频操作；桌面或第三方运行时缺失时明确失败。
- **FR-020**: MUST 提供明确的开发启动、停止、重启、显示目标与配置入口；保持当前REST/SSE和流端口语义，不额外建设完整旧管理后台的长期兼容工程。
- **FR-021**: MUST 保留媒体格式兼容范围，不将本次重构解释为无缝转场、帧同步或所有环境均可播放的保证。
- **FR-022**: MUST 以小步源码提交和版本恢复支持开发，不以生产切流、长期双轨运行、业务逆迁移或回退时限作为本次需求。
- **FR-023**: MUST 支持在独立测试目录初始化新数据；不要求迁移旧数据，不自动删除现有数据库/媒体，也不将源码版本恢复等同数据恢复。
- **FR-024**: MUST 区分控制客户端与播放执行主机；Windows/Android客户端均可连接Windows播放主机，Android不运行Office或多屏播放器，退出任一控制客户端不关闭主机播放。
- **FR-025**: MUST 为命令、窗口、源、进程、准备任务和迁移步骤提供关联诊断，日志不得包含密码、会话令牌或带凭据的完整地址。
- **FR-026**: MUST 验证共享业务合同、三端控制流程和Windows实际播放；用开发测试机即可，不要求现场维护/上线演练，不把未执行硬件测试说成通过。
- **FR-027**: MUST 同步技术栈治理、依赖锁文件和相关规范；通过版本管理恢复代码，保留必要安全/清理约束，不引入生产发布治理工程。
- **FR-028**: MUST 使用共享响应式样式和可访问交互，覆盖桌面与Android触控、返回、键盘/安全区域；平台壳不复制一套业务页面。
- **FR-029**: MUST 支持配置播放主机、验证连接、登录、状态同步和断线/回前台后重连；切换主机时清除旧会话/状态，离线不排队自动重放播控命令。
- **FR-030**: MUST 限制客户端原生权限与外部导航，正确处理文件选择/上传/下载；不把来自网页或媒体源的任意内容赋予系统文件或进程控制权限。

### Key Entities

- **媒体源与派生资源**：源标识、类型、位置、版本、预览、备注和页内媒体。
- **窗口会话与实际状态**：逻辑输出、显示目标、当前源、已确认放映模式和错误。
- **有序指令及执行凭据**：目标、内容、顺序、所有者、重试、完成证据。
- **预案与全局运行策略**：三态配置、大屏模式、系统音量和固定静音。
- **背景音频状态与列表**：独立音频目标、播放顺序、进度和循环。
- **放映所有权与准备任务**：唯一原生放映、缓存导出及其排队/失败状态。
- **预热资源与引用**：来源版本、所在窗口、安全上下文、健康度和释放结果。
- **控制端连接配置**：选择的播放主机、安全连接方式、本端会话和连接状态；不存储可自动重放的离线控制命令。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 网页、Windows客户端、Android客户端均通过相同的核心业务用例，未批准业务差异为0；三端使用共享页面，样式/壳适配不得破坏原控制规则。
- **SC-002**: 100 次执行前崩溃恢复中有效命令保留率 100%；1000 次背景音频并发写入/确认测试中误删和无序执行为 0。
- **SC-003**: 100 次执行后确认丢失测试中，没有一次未经核对的非幂等重复动作；不确定结果均能定位并要求明确处置。
- **SC-004**: 同时展示四个文稿的测试中本系统动态放映最多一路，其余使用有效静态回退；源版本错误和模式误报为 0。
- **SC-005**: 同窗口两个健康预热网页连续切换 50 次，新增导航为 0，登录、滚动和脚本状态保持；直播持续预热 10 分钟后仍可切入。
- **SC-006**: 在记录硬件、媒体和网络条件的开发测试机上，1000次普通控制的95%在1秒内开始执行；健康预热内容切换的95%在300毫秒内显示。冷打开和网络故障另行记录。
- **SC-007**: 20次正常启停与10次故障退出测试中，自有资源清理均有结果，误杀非本系统进程为0；关闭控制客户端时主机播放不被关闭。
- **SC-008**: 新测试目录可独立初始化并通过数据/认证用例，不依赖旧库；版本恢复说明明确覆盖源码而非数据库/媒体，自动破坏现有数据的行为为0。
