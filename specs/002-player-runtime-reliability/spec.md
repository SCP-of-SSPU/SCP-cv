# Feature Specification: 播放器 Runtime 可靠性与热切换

**Feature Branch**: `main`

**Created**: 2026-08-30

**Status**: In Review（自动化完成，等待 Windows 多屏实机验收）

**Input**: User description: "修复播放器 Runtime 审查中的全部 P1/P2/P3；彻底删除双显示器共同显示一个窗口；系统同时只允许一个 PowerPoint COM 放映，其余演示文稿使用 PDF；网页等需加载内容预热后像切换窗口一样仅切换显示；完成后重点 review 播放适配器与第三方集成。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 指令可靠执行与安全退出 (Priority: P1)

现场操作人员发出播放或背景音频指令后，系统必须保证指令要么被真实播放器执行并确认，要么保留为可恢复状态；关闭多窗口播放器时，各子进程必须先完成资源清理。

**Why this priority**: 丢失指令或强制终止播放器会直接造成现场画面、音频和第三方进程状态不可预测。

**Independent Test**: 在指令投递、执行和退出边界注入崩溃、并发写入及超时，验证命令不会静默丢失，子播放器能先协作退出并清理资源。

**Acceptance Scenarios**:

1. **Given** 一条待执行播放指令，**When** 播放器领取后在实际执行前退出，**Then** 指令仍可在播放器恢复后重新领取。
2. **Given** 背景音频正在消费旧指令，**When** 同时写入新指令，**Then** 新指令不会被旧指令的确认操作删除。
3. **Given** 多个独立播放器子进程正在运行，**When** 父进程收到退出请求或任一子进程结束，**Then** 其余子进程先收到协作式退出请求，并在超时后才允许强制终止。
4. **Given** 轮询线程或演示文稿工作线程关闭超时，**When** 控制器停止，**Then** 系统明确记录失败且不会宣称资源已经安全停止。

---

### User Story 2 - 只暴露真实可用的播放能力 (Priority: P1)

操作人员只能看到和调用当前媒体类型真正支持的操作；已废弃的左右拼接显示功能不再出现在界面、接口、文档或运行数据中。

**Why this priority**: 当前存在返回成功但播放器不执行的入口，会让现场人员误判系统状态。

**Independent Test**: 对每类媒体调用支持和不支持的控制动作，并检查接口响应、会话状态和播放器真实状态一致；全仓搜索不再出现可运行的左右拼接入口。

**Acceptance Scenarios**:

1. **Given** 图片、网页、直播或演示文稿等不同媒体，**When** 用户调用不受支持的控制操作，**Then** 系统返回明确的不支持错误且不会伪造状态变化。
2. **Given** 用户打开显示设置，**When** 选择输出目标，**Then** 只能为一个播放器窗口选择一个显示器。
3. **Given** 旧数据库仍保存左右拼接状态，**When** 升级完成，**Then** 会话被迁移为单屏且废弃字段不再参与任何合同或界面。

---

### User Story 3 - 单 PowerPoint COM 与 PDF 并发放映 (Priority: P1)

现场同时展示多个演示文稿时，全系统最多只有一个演示文稿使用 PowerPoint COM；其它演示文稿使用准备好的 PDF 放映，不得再启动额外 COM 实例。

**Why this priority**: PowerPoint 多实例和跨进程 COM 竞争是播放器故障最集中的来源。

**Independent Test**: 并发打开两个以上演示文稿，验证只有一个系统级 COM 槽位持有者，其余窗口以 PDF 正常翻页；槽位竞争和 PDF 缺失都有明确状态。

**Acceptance Scenarios**:

1. **Given** 没有活动 PowerPoint COM 放映，**When** 首个允许 PowerPoint 模式的演示文稿打开，**Then** 它取得唯一系统槽位并使用 COM。
2. **Given** 系统槽位已被占用，**When** 另一个窗口打开演示文稿，**Then** 它直接使用 PDF 放映且不创建第二个 COM 实例。
3. **Given** 系统槽位已被占用且目标演示文稿没有可用 PDF，**When** 打开该演示文稿，**Then** 系统保持原画面或黑屏安全态并报告可诊断错误，不突破单实例限制。
4. **Given** PDF 回退窗口正在放映，**When** COM 槽位后来释放，**Then** 当前窗口保持 PDF 模式，直到用户明确重新打开该源。

### User Story 4 - 媒体资源热切换 (Priority: P1)

操作人员切换到已经预热的网页等内容时，只改变哪个已加载资源可见，不重新加载内容；切离后资源回到后台保活，后续再次切入仍保留页面状态。

**Why this priority**: 网页和直播是高频内容，重复冷加载会产生长时间黑屏、登录丢失和现场体验中断。

**Independent Test**: 在网页中写入可观察状态后反复切入切出，验证页面对象和状态保持不变、没有新的导航加载；直播预热长时间运行后仍可认领或已自动续热。

**Acceptance Scenarios**:

1. **Given** 网页已经完成预热，**When** 首次切入，**Then** 系统复用该网页实例并只切换父容器和可见性。
2. **Given** 网页已在前台产生滚动、登录或脚本状态，**When** 切离再切回，**Then** 状态保持且不会刷新页面。
3. **Given** 两个预热网页在后台保持，**When** 用户在两者之间切换，**Then** 切换行为等价于桌面窗口显隐，不发生重复网络加载。
4. **Given** 直播源配置为持续预热，**When** 长时间运行后再切入，**Then** 仍能认领有效连接，或系统在后台自动更新过期连接。

---

### User Story 5 - 可诊断且可维护的第三方集成 (Priority: P2)

维护人员能够确认 VLC、PowerPoint、窗口、临时文件和预热资源是否清理成功；播放器核心文件保持可导航，运行设计文档与真实模块一致。

**Why this priority**: 第三方异常不可完全避免，但必须防止静默残留；超大文件和漂移文档会放大后续修复风险。

**Independent Test**: 让每个清理步骤分别抛错，验证后续释放继续执行且日志可定位；检查拆分后文件规模和文档引用。

**Acceptance Scenarios**:

1. **Given** VLC 停止或解绑媒体失败，**When** 适配器关闭，**Then** 后续播放器、媒体和实例释放仍分别执行。
2. **Given** 临时源删除失败，**When** 媒体离场，**Then** 系统记录可定位的警告并保留可重试状态。
3. **Given** PowerPoint COM 初始化失败，**When** 有任务等待执行，**Then** 所有任务收到明确失败且不会继续 COM 操作。
4. **Given** 维护人员阅读播放器设计，**When** 按文档定位 GPU、窗口和流模块，**Then** 文件名和职责与当前代码一致。

### Edge Cases

- 播放命令已执行但确认写库失败时，恢复后可能重复投递；各命令必须具备幂等边界或可识别的执行令牌。
- 新的终止类命令到达时，已在执行的旧打开命令不能被数据库删除动作伪装为“从未执行”。
- 父进程和子进程同时收到退出信号时，重复退出请求必须幂等。
- 系统级 COM 槽位持有进程崩溃后，锁必须可由新进程恢复，且不得误杀用户自行启动的 PowerPoint。
- PDF 回退必须使用与源版本匹配的缓存，过期或生成失败的 PDF 不得作为成功打开处理。
- 预热资源与请求 URI、源版本或安全上下文不匹配时必须丢弃并重新加载。
- 多个预热网页归还同一源键时，旧资源必须被明确释放，不能成为不可达后台页面。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在播放器真实执行完成后才确认并移除播放命令。
- **FR-002**: 系统 MUST 为已领取但未完成的命令提供崩溃恢复机制，并防止多个播放器同时消费同一窗口命令。
- **FR-003**: 背景音频 MUST 使用不会覆盖独立操作的有序命令记录，并以记录身份确认，禁止无条件清空共享槽位。
- **FR-004**: 多窗口父进程 MUST 先请求子播放器协作退出、等待资源清理，并仅在明确超时后强制终止。
- **FR-005**: 控制器 MUST 在释放适配器、预热池和第三方工作线程前确认轮询线程已停止。
- **FR-006**: PowerPoint 工作线程关闭超时或初始化失败 MUST 成为可观察失败，不得继续执行 COM 操作或宣称安全停止。
- **FR-007**: 系统 MUST 删除左右拼接模式的前端入口、接口合同、服务逻辑、运行模型字段、文档和非历史测试；数据库升级 MUST 将现有会话安全归一为单屏。
- **FR-008**: 单屏显示目标选择 MUST 保留。
- **FR-009**: 每类媒体 MUST 声明其支持的操作能力；服务层 MUST 在入队前拒绝不支持操作。
- **FR-010**: 播放器 MUST 仅依据适配器真实状态回写播放状态，不得在静默 no-op 后写入乐观状态。
- **FR-011**: 全系统 MUST 通过可崩溃恢复的共享槽位保证同一时刻最多一个 PowerPoint COM 放映实例。
- **FR-012**: 当共享槽位被占用时，演示文稿 MUST 自动使用与源版本匹配的 PDF；PDF 不可用时 MUST 明确失败且不得创建第二个 COM 实例。
- **FR-013**: 已经以 PDF 打开的窗口 MUST 保持 PDF，槽位释放不得触发自动 COM 切换。
- **FR-014**: 网页预热 MUST 保留真实页面实例；切入切出 MUST 只执行容器迁移和显隐，不得导航到空白页或重新加载。
- **FR-015**: 持续预热资源 MUST 在过期前续热，或在有效性检查证明仍可用时继续认领，不能仅因固定存活时间而无条件冷启动。
- **FR-016**: 预热池 MUST 对同一源的资源替换执行显式清理，并在退出时释放所有前台、后台和在途资源。
- **FR-017**: VLC 等多步骤清理 MUST 相互独立执行，一个步骤失败不得跳过后续释放。
- **FR-018**: 临时源和第三方资源清理失败 MUST 记录资源类型、窗口/源标识、失败阶段和可重试结果。
- **FR-019**: `ppt_window.py`、`window.py` 和 `srt_stream.py` MUST 拆分为职责清晰且单文件不超过项目阈值的模块。
- **FR-020**: 播放器 Runtime 设计文档 MUST 更新为当前文件名、职责和行为，并删除已废弃拼接功能描述。
- **FR-021**: 每一项修复 MUST 先有自动化回归测试；PowerPoint、VLC、多屏和网页热切换 MUST 有 Windows 实机验证步骤。
- **FR-022**: 实现完成后 MUST 对播放适配器和第三方集成进行单独审查，重点覆盖 PowerPoint 单槽、PDF 回退、VLC、网页保活、MediaMTX 和退出清理。

### Key Entities

- **播放命令记录**: 一次独立播放器操作，包含目标窗口、参数、领取状态、执行身份、确认状态和恢复信息。
- **背景音频命令记录**: 一次独立背景音频操作，与播放器命令具有相同的有序消费和确认语义。
- **PowerPoint 系统槽位**: 跨播放器进程共享的唯一 COM 放映所有权，包含持有者身份、进程生存证据和恢复规则。
- **演示文稿放映选择**: 记录某次打开实际采用 PowerPoint 或 PDF，以及选择原因和失败状态。
- **预热资源**: 已加载但可处于后台的网页、视频、音频或直播资源，包含源版本、有效性、前后台状态和归属容器。
- **媒体能力集**: 每种媒体类型可执行的控制动作集合，用于接口校验和界面呈现。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 100 次“领取后、执行前”崩溃注入中，恢复后的可执行命令保留率为 100%。
- **SC-002**: 在 1000 次背景音频并发写入/确认测试中，没有新命令被旧命令确认误删，且独立操作保持预期顺序。
- **SC-003**: 正常退出时所有子播放器均进入资源清理路径；只有超过配置超时时间的进程才被强制终止并产生明确日志。
- **SC-004**: 全仓运行合同中不再暴露左右拼接选择；升级后所有活动会话均为单屏。
- **SC-005**: 并发打开 4 个演示文稿时，系统检测到的 PowerPoint COM 放映实例始终不超过 1，其余窗口可使用 PDF 独立翻页。
- **SC-006**: 对已预热网页连续切换 50 次，页面实例身份保持不变、页面状态不丢失、网络导航次数不增加。
- **SC-007**: 持续预热直播源在运行 10 分钟后切入时仍可认领有效连接，且不因固定时长直接冷启动。
- **SC-008**: 对 VLC 各清理步骤逐一注入失败时，其余清理步骤执行率为 100%，每个失败均有可定位日志。
- **SC-009**: 三个超阈值文件拆分完成，播放器设计文档中的文件引用和行为说明与代码一致。
- **SC-010**: 播放器专项测试、后端完整测试、前端类型检查与构建、OpenAPI 校验和代码检查全部通过。
- **SC-011**: 播放适配器与第三方集成复审不存在未处置的 P1/P2/P3 finding；无法自动验证的现场行为均有可重复实机步骤和结果记录。

## Assumptions

- 保留一个播放器窗口对应一个显示器的单屏选择；仅删除一个窗口跨两个显示器的左右拼接能力。
- PowerPoint 单实例限制是整台现场主机范围，而不是单进程或单窗口范围。
- PDF 回退使用项目现有演示文稿 PDF 资源；缺失时优先安全失败，不临时突破 COM 限制。
- 已用 PDF 打开的窗口不会因槽位释放自动升级为 COM，避免现场画面突变。
- 网页热切换优先保留 DOM、登录、滚动和脚本状态；关闭播放器或显式禁用预热时才释放。
- 本次范围包含审查中列出的全部 P1、P2 和 P3。
